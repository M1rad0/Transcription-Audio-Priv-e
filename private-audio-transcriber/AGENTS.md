## Project name

Private Audio Transcriber V1

## Project purpose

This project is a local-first private audio transcription system.

The user uploads an audio file through a local Next.js application. The local backend-for-frontend encrypts the audio, sends it to a custom RunPod Serverless worker, receives two outputs, and displays/exports them.

Expected outputs per job:

- `raw.txt`: raw transcription generated by faster-whisper.
- `modified.txt`: corrected and structured version generated by a lightweight local LLM running inside the RunPod worker.
- `result.json`: structured JSON with metadata, transcript segments and cleanup status.

The system is designed to process approximately:

- 120 minutes of audio per day;
- 6 days per week;
- around 52 hours of audio per month.

The goal of V1 is not perfect transcription. The goal is a private, usable, human-reviewable transcription workflow with controlled GPU cost.

---

## Core V1 architecture

```text
Browser
→ Local Next.js app
→ Authenticated Next.js BFF API route
→ AES-GCM encrypted audio payload
→ RunPod Serverless custom endpoint
→ Python worker
→ temporary decryption in /tmp/job_xxx
→ faster-whisper transcription
→ lightweight local LLM correction
→ raw_text + modified_text + segments
→ cleanup temporary files
→ response to Next.js
→ user review/export
```

## Final V1 decisions

Use:

- Next.js with App Router for the local application.
- Next.js API routes as the BFF.
- Simple local authentication.
- RunPod Serverless custom endpoint.
- Python RunPod worker.
- faster-whisper as the main transcription engine.
- A lightweight local LLM inside the same RunPod worker for `modified_text`.
- AES-256-GCM encryption before sending audio to RunPod.
- HKDF-derived per-file encryption key.
- Temporary files under `/tmp/job_xxx` on the worker.
- Cleanup in `finally`.

Do not use in V1:

- Spring Boot.
- OpenAI API.
- Hugging Face Inference Endpoint.
- ElevenLabs API.
- Google Speech API.
- Any external transcription API.
- Audio enhancement.
- DeepFilterNet.
- RNNoise.
- Double transcription.
- Advanced diarization.
- Public SaaS multi-tenant architecture.
- Payment system.
- Complex role management.
- Database unless explicitly requested later.

Hugging Face Hub is allowed only as a model source/cache inside the RunPod worker. It must not be used as an inference API.

## BFF anti-abuse rules

The BFF is the main anti-cost barrier.

The browser must never call RunPod directly.

The BFF must check before calling RunPod:

- user is authenticated;
- file exists;
- file size <= 12 MB;
- file extension is allowed;
- optional one active job at a time;
- optional daily job limit;
- optional daily estimated audio limit;
- required environment variables exist.

If validation fails, do not call RunPod.

RunPod secrets must remain server-side only.

Required environment variables:

```env
RUNPOD_API_KEY=
RUNPOD_ENDPOINT_ID=
MASTER_KEY_BASE64=
```

Optional:

```env
MAX_AUDIO_SIZE_MB=12
MAX_JOBS_PER_DAY=
ALLOW_CONCURRENT_JOBS=false
```

## Encryption scheme

The audio file must be encrypted before being sent from the Next.js BFF to RunPod.

Use:

- AES-256-GCM.
- HKDF.
- A master key shared between Next.js BFF and RunPod worker through environment variables.

For each file:

1. Generate a unique `job_id`.
2. Generate a unique `salt`.
3. Generate a unique `audio_nonce`.
4. Derive a per-file key using HKDF from:
   - `MASTER_KEY_BASE64`
   - `salt`
   - `job_id`
5. Encrypt the audio using AES-GCM with:
   - derived per-file key
   - `audio_nonce`
6. Send encrypted payload to RunPod.

Payload sent to RunPod:

```json
{
  "job_id": "job_xxx",
  "filename": "audio.mp3",
  "encrypted_audio_base64": "...",
  "salt_base64": "...",
  "audio_nonce_base64": "...",
  "options": {
    "language": "fr",
    "generate_modified": true
  }
}
```

Rules:

- Never reuse the same AES-GCM key/nonce pair.
- `salt` is not secret.
- `audio_nonce` is not secret.
- `MASTER_KEY_BASE64` is secret.
- Never send `MASTER_KEY_BASE64` to the browser.
- Never log keys, audio files, full transcripts, or encrypted payloads.
- Decrypt only temporarily inside the RunPod worker.
- Cleanup temporary files in `finally`.

---

## RunPod worker responsibilities

The Python worker must:

- receive the encrypted payload;
- validate required fields;
- read `MASTER_KEY_BASE64` from environment variables;
- derive the per-file key using the same HKDF scheme;
- decrypt the audio into `/tmp/job_xxx`;
- transcribe with faster-whisper;
- generate `raw_text`;
- pass `raw_text` to the local LLM corrector;
- generate `modified_text`;
- return JSON result;
- delete `/tmp/job_xxx` in a `finally` block;
- avoid sensitive logs.

Expected output:

```json
{
  "job_id": "job_xxx",
  "status": "success",
  "engine": "faster-whisper-large-v3-turbo",
  "language": "fr",
  "duration_seconds": 1200,
  "raw_text": "...",
  "modified_text": "...",
  "segments": [
    {
      "start": 0.0,
      "end": 8.4,
      "text": "..."
    }
  ],
  "cleanup": {
    "temp_files_deleted": true
  }
}
```

## Local LLM correction rules

The local LLM must improve only the form of the transcription.

It may:

- add punctuation;
- create paragraphs;
- improve readability;
- correct obvious spelling issues.

It must not:

- add information;
- invent missing words;
- change meaning;
- summarize unless explicitly requested;
- remove uncertain content silently.

Correction prompt:

```text
Tu reçois une transcription brute générée automatiquement.
Ta tâche est de corriger uniquement la forme : ponctuation, paragraphes, orthographe évidente et lisibilité.
Tu ne dois pas ajouter d’informations.
Tu ne dois pas inventer de mots.
Tu ne dois pas changer le sens.
Si un passage semble incomplet, ambigu ou incohérent, conserve-le et ajoute [à vérifier].
Retourne uniquement le texte corrigé.
```

## Security rules

Never expose these to frontend code:

- `RUNPOD_API_KEY`
- `MASTER_KEY_BASE64`
- `SESSION_SECRET`
- `AUTH_PASSWORD_HASH`
- any worker secret

Never log:

- raw audio;
- decrypted audio path if it reveals sensitive names;
- full transcription;
- full encrypted payload;
- secrets;
- API keys.

Use technical logs only:

- job id;
- status;
- timings;
- file size;
- error type;
- cleanup status.

The BFF is the main security and anti-cost barrier.

Request HMAC signing between BFF and worker is optional in V1. If added, it is a secondary defense only. Do not add fake security mechanisms that do not provide real protection.

## Definition of Done V1

V1 is done when:

- User can log in locally.
- User can upload one supported audio file up to 12 MB.
- BFF validates the file before any RunPod call.
- BFF encrypts the file using AES-256-GCM with per-file derived key.
- Browser never sees RunPod or encryption secrets.
- RunPod worker decrypts audio temporarily.
- faster-whisper generates `raw_text`.
- local LLM generates `modified_text`.
- UI displays both outputs.
- User can export `raw.txt`.
- User can export `modified.txt`.
- User can export `result.json`.
- Worker deletes all temporary files after each job.
- Worker returns cleanup status.
- No external transcription API is used.
- No audio enhancement is performed.
- No double transcription is performed.
- RunPod workers are configured to control cost.
- Basic test plan is completed.
